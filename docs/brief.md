# Intent: ตรวจสิ่งที่ควรรู้ก่อนสั่งซื้อสินค้าเพื่อนำมาขาย

Status: accepted
Owner: ทีมผู้ใช้ 3 คน

## Problem and why it matters

ผู้ซื้ออาจไม่เข้าใจว่าข้อความในตัวเลือกสินค้ามีผลต่อสิ่งที่จะได้รับ และไม่รู้ว่าต้องตรวจประเด็นใดเพิ่มเติม ผู้ใช้เล่าว่าได้รับกระติกที่ลายเป็นสติกเกอร์ ทั้งที่เข้าใจจากภาพว่าเป็นงานสกรีน แล้วจึงย้อนพบคำจีนในตัวเลือกสินค้า

## Desired outcome and success

ผู้ซื้ออัปโหลดหน้าเว็บที่บันทึกไว้ ยืนยันตัวเลือกที่จะซื้อ 1–3 ตัวเลือกจากหน้าเดียวกันและบริบทการซื้อ แล้วได้รับหนึ่งรายงานต่อกรณีซื้อ มีรายการประเด็นที่ควรตรวจเรียงตามความสำคัญ พร้อมหลักฐาน เหตุผล สิ่งที่ยังไม่ทราบ และคำถามที่นำไปถามผู้ขายได้ ประเด็นร่วมแสดงครั้งเดียวและประเด็นเฉพาะผูกกับตัวเลือกที่เกี่ยวข้อง

ตามข้อตกลงในขั้น Design ผู้ใช้ให้บริบทเริ่มต้นมากหรือน้อยได้ ระบบอ่านเว็บและบริบทก่อน แล้วถามเฉพาะเรื่องที่คำตอบเปลี่ยนงานตรวจหรือคำแนะนำ สูงสุด 3 รอบ รอบละไม่เกิน 5 ข้อ แสดงพร้อมกันทั้งรอบและใช้คำตอบปรับรอบถัดไป หากข้อมูลเพียงพอให้ข้ามรอบถาม ผู้ใช้ตอบไม่ทราบหรือข้ามได้ จากนั้นระบบออกรายงานพร้อมเรื่องค้างโดยไม่เดาความต้องการ การถามบริบทผู้ซื้อเป็นงานหลัก ส่วนรอบรับคำตอบจากผู้ขายยังเป็นงานเสริม

ฉากหลักต้องค้นพบประเด็นที่ผู้ซื้อไม่ได้ถามเอง เช่น คำเกี่ยวกับภาพแปะในตัวเลือก และข้อมูลฝา PP/รายงานทดสอบที่ทำให้ควรตรวจต่อ โดยไม่ใส่คำใบ้เรื่องสติกเกอร์ในโจทย์เดโม และไม่ฟันธงเทคนิคตกแต่งหรือความปลอดภัยเกินหลักฐาน

ตัวอย่างผลที่ต้องแยกได้: รายการวิธีปรับแต่งทั่วไประบุว่ารองรับสกรีน ไม่ยืนยันว่าตัวเลือกที่จะซื้อเป็นงานสกรีน การระบุว่าไม่มีรายงานทดสอบไม่เท่ากับพิสูจน์ว่าสินค้าไม่ปลอดภัย

## Affected users and systems

ผู้ซื้อสินค้าเพื่อนำมาขายทั่วไป เริ่มจากกระติกเก็บเครื่องดื่มในเคสจริงที่ได้รับ ใช้ HTML กับโฟลเดอร์ประกอบที่บันทึกจากหน้า TTP Cargo หมายเลขสินค้า 1035537244639 เป็นหลักฐานตั้งต้น ยังไม่ได้ตรวจสินค้าจริงหรือประวัติการสั่งซื้อ

ผู้ซื้อเปิดแอปหลัง restart แล้วทำเคสล่าสุดต่อได้ โดยกู้ SKU หลักฐาน และคำตอบที่ส่งแล้ว

## Scope and exclusions

ตรวจเบื้องต้น 3 กลุ่ม: สินค้าและตัวเลือกตรงความต้องการหรือไม่ การใช้งานทำให้ต้องตรวจเรื่องใดเพิ่ม และข้อมูลรองรับรุ่นที่จะซื้อเพียงพอหรือไม่

รับ ZIP ของ HTML และโฟลเดอร์ประกอบ แสดงตัวเลือกให้ผู้ใช้ยืนยัน ไม่ใช้ค่าเริ่มต้นของหน้าเป็นข้อยืนยันว่าผู้ซื้อเลือกสินค้านั้น

ใช้ชุดเอกสารทางการที่คัดไว้เป็นความรู้ภายนอกหลัก ไม่ค้นเว็บอิสระสดในรุ่นหลัก ต้องแสดงแหล่งอ้างอิงและสิ่งที่อยู่นอกขอบเขตชุดความรู้นี้

รุ่นหลักจบที่รายงานและแผนตรวจต่อ ไม่รวม scraping อัตโนมัติ ความน่าเชื่อถือผู้ขาย ภาษี ค่าขนส่ง กำไร การส่งข้อความจริง การสั่งซื้อ หรือการรับรองว่านำเข้าได้/ปลอดภัย/ตรวจครบทุกความเสี่ยง

การรับคำตอบผู้ขายและประเมินใหม่เป็นงานเสริมที่ผู้ใช้อยากทำ แต่ตัดได้โดยไม่ทำให้รุ่นหลักไม่สมบูรณ์

## Constraints

มี dev 3 คน วางแผนงานหลัก 6 ชั่วโมงจากช่วงงานแข่ง 7 ชั่วโมง งานพัฒนาใหม่ที่ใช้ตัดสินต้องเกิดในวันแข่ง เอกสารนี้เป็นการเตรียมแนวคิดและขอบเขต ยังไม่ใช่การเริ่มพัฒนา

ทีมถนัด Python เป็นส่วนใหญ่และพร้อมให้ AI ช่วยเขียนโค้ด ผู้ใช้ระบุว่ามีเครดิต OpenAI $100 แล้ว ยังไม่ได้ทดลองเรียก API หรือวัดต้นทุนต่อรอบ การเลือกโมเดลและเครื่องมือหน้าเว็บเป็นรายละเอียดของ Design ไม่จำเป็นต้องใช้หลายภาษาเพียงเพราะ AI เขียนให้ได้

คำตอบล่าสุดในขั้น Design: ผู้ใช้เลือก TypeScript สำหรับ frontend เพื่อทำหน้าเว็บ ส่วน Python/FastAPI backend และ React/Vite ได้รับการยอมรับใน Design แล้ว ไม่เปลี่ยนขอบเขตพฤติกรรมหลัก

Feedback หลังลอง mock: ใช้ UI ภาษาอังกฤษเป็นหลักเพื่อกรรมการต่างชาติ แปลข้อมูลสินค้าที่ใช้ตัดสินใจให้ตรงบริบทโดยเก็บข้อความจีนต้นฉบับ และแสดงรูปตามตัวเลือก ผู้ใช้ยอมรับ batch 1–3 ตัวเลือกจากหน้าเดียวต่อกรณีซื้อแล้ว คำถามปรับตามคำตอบสูงสุด 15 ข้อตลอด 3 รอบ ตลาดเป้าหมายยังเป็นผู้ซื้อนำมาขายในไทย

วันที่ 17 พ.ย. 2569 ผู้ใช้ยอมรับแนวทาง Purchase review refinement และให้ปรับ mock รายละเอียดพฤติกรรมที่ยอมรับอยู่ใน [spec](spec.md#purchase-review-refinement-ที่ยอมรับแล้ว) การยอมรับนี้ไม่เปลี่ยนขอบเขตเป้าหมายหรือเริ่ม Build แอปจริง

ตามคำตอบขั้น Design ให้เน้นเดโม local ก่อน ผู้ใช้อยาก deploy หากมีเวลา แต่การมีเว็บสาธารณะไม่เป็นเงื่อนไขความสำเร็จ การ deploy อยู่นอกงาน Design ปัจจุบัน

ยังไม่อ้างว่าดีกว่า ChatGPT ในด้านความแม่นยำหรือการประหยัดเงิน เพราะยังไม่มีผลวัดเปรียบเทียบ
